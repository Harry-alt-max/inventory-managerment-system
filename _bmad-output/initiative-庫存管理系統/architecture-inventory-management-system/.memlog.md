- (decision) 範式： Django 分層單體（MVT）+ service 層；四個 app 對應四個 epic（accounts／catalog／stock／sales）— 綁定全專案結構；防止四個 epic 各自發明邊界而做出不相容的模組
- (decision) 依賴方向： view → service → model；app 之間只透過 service 與公開模型往來，禁止跨 app 直接寫入他方 model — 防止隱式耦合與跨邊界寫入
- (decision) 庫存寫入唯一路徑：任何改變庫存數量的動作只能經過 domain service 的一個 use case 函式（內含 transaction.atomic 與守衛規則），view 不得直接改庫存 — 防止交易邊界散落與守衛規則被繞過
- (decision) 守衛規則集合：銷售扣減只能經銷貨 use case、跨倉庫存變動必須對應一張調貨單、庫存數量不得為負、異動與銷貨紀錄僅追加 — 綁定 R6 R11 R12 R14 R16 R19
- (decision) 權限模型： Django auth + Group/Permission，PRD FR-2 的權限矩陣展開成 permission codename，view 層宣告所需權限 — 防止兩套權限系統並存與僅靠前端隱藏按鈕
- (decision) 認證： session + CSRF，前端開發時以 Vite proxy 同源呼叫 Django，不引入第二套 token 系統 — 防止認證雙軌與 token 生命週期維護
- (decision) API 契約： 路徑前綴 /api/v1/；欄位沿用 DRF 預設 snake_case 不加轉換層；錯誤統一為 {code, detail, field_errors} 包絡 — 防止前後端各自發明格式
- (decision) 識別碼分離： 資料庫內部主鍵與業務編號分開；商品編號 INV- 加 6 碼流水號、採購批次流水號 PO-YYYYMMDD-序號，皆由 DB sequence 產生且建立後不可修改 — 防止用顯示編號當外鍵或事後改號
- (decision) 數值型別： 數量為整數；單價、總價、金額為 Decimal(12,2)；捨入一律 ROUND_HALF_UP — 防止浮點誤差與不同端各自捨入
- (decision) 時間： 一律以 UTC 儲存，顯示層轉 Asia/Taipei — 防止跨時區計算與顯示不一致
- (decision) 成本基準 FIFO： 成本 = 依序消耗的批次採購單價 × 數量；批次原始單價與數量不得被彙總成本取代 — 綁定 R18，防止 E2 預存彙總值後無法改基準
- (decision) 刪除策略： 交易類資料（庫存異動、銷貨紀錄、批次）不得 update／delete，ORM 層封鎖；設定類資料（供應商、商品）以 is_active 軟刪除 — 防止稽核資料被改寫
- (decision) schema 變更唯一途徑為 Django migrations；跨 app 的 FK 只允許指向被依賴 app 的公開模型 — 防止手改 schema 與跨邊界外鍵
- (decision) 測試紀律： pytest + pytest-django + factory_boy；固定 seed 資料集；帳面等式（入庫−領用−調出+調入−銷貨=0）測試必備；測試使用獨立資料庫 — 綁定 Done when 第 2 項
- (decision) 資料庫： PostgreSQL 18.6（本機既有 AILearn），單一 schema；連線憑證由 pgpass.conf 環境變數提供，不進版控 — 防止憑證外洩與多庫分裂
- (decision) 前端： Vite + React + TypeScript；開發以 proxy 同源呼叫 Django，正式由 Django（WhiteNoise）服務 build 產物 — 防止兩套靜態資源服務並存
- (decision) 錯誤處理： domain 例外在單一 DRF exception handler 轉為統一錯誤包絡；業務錯誤不得回應 500 — 防止前端各自解析錯誤形狀
- (version) web 查證的當前版本： Django 6.1（DRF 3.17.1 官方支援 5.2/6.0/6.1）、djangorestframework 3.17.1、psycopg 3.3.x、pytest 8.x、pytest-django 4.x、factory_boy 3.3.x、WhiteNoise 6.12.0、gunicorn 25.3.0、Node.js 22.18.0（Vite 8 需 20.19+/22.12+）、Vite 8.0、React 19.2.x、TypeScript 5.x、PostgreSQL 18.6、Python 3.14.7
- (assumption) 部署與環境： v1 以本機部署與本機 PostgreSQL 為準，不做容器化與正式環境拓撲（課業規模）— 已列入 Deferred
- (question) 前端資料層與快取策略（React Query 或同等方案）未裁決，歸 E1 骨架 story 在實作時決定
- (event) 教練模式：使用者拍板 4 個 django app、React SPA + DRF、Django auth + Group/Permission、pytest + factory_boy、session + CSRF、service 層唯一寫入路徑、DRF 預設契約加統一錯誤包絡
- (decision) AD-19 登入失敗計數存 DB 第5次失敗鎖 15 分鐘 所有失敗回應同一訊息與錯誤碼 不透露帳號存在性
- (decision) AD-20 供應商統編/倉庫編碼/位置代碼/商品編號/批次流水號 的唯一性以 DB UNIQUE 落實 衝突回 409 並在 field_errors 指回既有資料
- (decision) AD-21 建議調貨來源＝可用量最大且能覆需求量者 同量取倉碼升序 無倉可覆蓋時回明確無庫存狀態碼 建議僅唯讀
- (decision) AD-22 銷貨單狀態機只有 draft 與 submitted draft 不扣庫存 submitted 內容不可改 取消銷貨以 append 反向沖銷單表達
- (decision) AD-23 設定分 base/dev/test/prod 四層 正式 DEBUG=False SECRET_KEY 與 ALLOWED_HOSTS 由環境變數注入 缺值即失敗
- (decision) AD-24 架構守門納入建置：import-linter 依賴契約 django-architectural-rules 阻斷 view 直接寫 model makemigrations --check 違規即失敗
- (decision) AD-25 效能基準為硬性非 deferred：1,000 商品/10,000 異動下清單與明細查詢 2 秒內回應 並以自動化測試守住 必要索引明確列出
- (decision) AD-26 提供唯讀報價試算端點 後端為毛利唯一計算者 成本缺時回 null 與 cost_status=unset 不得填 0
- (decision) AD-27 交付優先序：課業評分標準 > PRD > addendum > spine > 實作慣例 衝突時 spine 讓位
- (decision) AD-28 事實唯一 home：銷貨事實在 SALES_ORDER/LINE 庫存事實在 STOCK_MOVEMENT 以 sales 端 append-only 連結表 BATCH_CONSUMPTION 關聯 一次銷貨同一交易內完成
- (decision) AD-29 STOCK_LEVEL（商品×位置）是庫存數量唯一真相 由異動 use case 同交易更新 不得另以異動彙總提供第二個數字
- (decision) AD-30 銷貨行必填庫存位置 扣減回傳實際位置 可用量檢查與扣減同交易並對 STOCK_LEVEL 加鎖重驗
- (decision) AD-31 FIFO 排序鍵固定為入庫異動發生時間 同秒以批次主鍵升序 批次消耗明細持久化可逐筆回溯
- (decision) AD-32 actor 為 use case 顯式參數 禁 thread-local 紀錄保存帳號代號快照 跨 app 呼叫沿用傳入值
- (constraint) AD-6 補充 使用者密碼以 PBKDF2 或 Argon2 單向雜湊儲存 禁可降級演算法 不得出現明文密碼或自建密碼欄位
- (constraint) AD-12 補充 採購批次納入僅追加 交易類資料不得使用 is_active 軟刪除
- (constraint) AD-11 補充 批次建立後其單價數量採購日期不得修改 更正以新批次表達
- (constraint) AD-4 補充 領用用途只有客戶寄貨與臨時出貨 不存在銷貨用途 且領用不計毛利
