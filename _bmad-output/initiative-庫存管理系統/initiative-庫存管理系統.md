# 庫存管理系統

## Description

公司內部的進銷存後台，服務倉管、採購、銷售、會計四種職能：商品與批次有據可查、庫存異動留痕、銷售毛利即時算得出來、庫存低於水位的商品自動浮到採購的待辦清單。需求由課堂簡報與 PRD 定義，實作方式（後端框架、資料庫、架構模式）由 `bmad-architecture` 定案。

## Outcome

四種職能在同一份庫存真相上協作：任何人問「這批貨在哪、賣得掉嗎、賺不賺」，答案來自系統而不是跨部門追問（PRD SM-1、SM-3）。

## Requirements

1. **登入與錯誤處理** (R1, prd FR-1): 使用者可用帳號密碼登入；密碼錯誤一律回應「帳號或密碼錯誤」，同一帳號連續失敗 5 次暫時鎖定 15 分鐘。
2. **角色權限** (R2, prd FR-2): 倉管、採購、銷售、會計四種角色各自只能存取權限表允許的畫面與操作；越權呼叫被拒絕，會計角色任何寫入都被拒絕。
3. **操作留痕** (R3, prd FR-3): 每筆庫存異動與每張銷貨單都帶有非空操作人員，且與登入者一致。
4. **商品主檔** (R4, prd FR-4): 可建立含系統產生商品編號（`INV-` + 6 碼）、名稱、供應商、建議售價與預計毛利的主檔；缺必填欄位時拒絕儲存並指出缺哪一欄。
5. **商品查詢** (R5, prd FR-5): 可依名稱部分關鍵字查商品並看到庫存位置、庫存數量與所在倉庫；查不到時顯示空結果提示，結果數量與各位置加總一致。
6. **供應商資料** (R7, prd FR-7): 可維護含統編、公司名稱、聯絡人、電話的供應商；同統編不得重複，缺統編或公司名稱時拒絕儲存。
7. **採購批次** (R9, prd FR-9): 可建立含供應商、批次流水號（`PO-YYYYMMDD-序號`，序號同日全域遞增不重複）、單價、數量與自動計算總價的批次；缺單價或數量時不可儲存。
8. **倉庫與位置** (R10, prd FR-10): 可維護倉庫（唯一編碼）及其下庫存位置（同倉代碼唯一），並列出某倉所有位置及其存放商品與數量。
9. **入庫** (R11, prd FR-11): 可對指定倉庫與位置入庫（商品、數量、批次），庫存即時增加、產生一筆入庫異動；單價取自該批次，入庫畫面不另行輸入。
10. **領用** (R12, prd FR-12): 可從庫存領用商品並記錄用途（客戶寄貨／臨時出貨），不得超過可用數量，領用不計毛利。
11. **同倉移轉** (R13, prd FR-13): 可將商品由一個位置轉移至同一倉庫的另一位置，移出與移入同步變動，總庫存不變。
12. **跨倉調貨** (R14, prd FR-14): 可建立跨倉調貨單，產生移出與移入兩筆異動、總庫存不變，且異動可對應回該調貨單。
13. **異動紀錄** (R6, prd FR-6): 每次庫存變動行為產生一筆異動紀錄，含商品、操作人員、異動數量（入庫為正、移出／領用／銷貨為負）、日期、用途與批次；紀錄不可修改或刪除。
14. **補貨水位** (R8, prd FR-8): 可為商品設定整數水位並查詢所有庫存低於水位的商品（含現有庫存、水位、缺口、供應商）；補貨至水位（含）以上後自動離開清單。
15. **可售狀態查詢** (R15, prd FR-15): 銷售查商品時可見可用庫存、各倉可用量與建議調貨來源倉庫；無庫存時明確標示並給出可調貨來源。
16. **組合銷貨單** (R16, prd FR-16): 可將多項商品組成同一張銷貨單（同一商品不重複、可存草稿），送出時產生銷貨紀錄並扣減庫存；銷貨是銷售用途扣減庫存的唯一入口。
17. **折扣** (R17, prd FR-17): 可設定一階百分比折扣，折後金額 = 原價合計 ×（1 − 折扣率）並顯示小數點後兩位；折扣率不在 0～100% 範圍內時拒絕儲存。
18. **毛利與建議售價** (R18, prd FR-18): 每筆銷貨顯示毛利（折後金額 − 成本）與建議售價；商品無入庫成本紀錄時顯示「成本未設定」而非 0。
19. **銷貨紀錄** (R19, prd FR-19): 銷貨紀錄含操作人員、日期、數量、金額與對應批次，可依日期或銷貨單號查詢；不可刪除，僅能反向沖銷並留下紀錄。
20. **帳號生命週期** (R20, prd FR-20): 可建立帳號、指派角色、停用帳號與重設密碼；停用帳號不可登入，既有紀錄保留。

## Constraints

1. **參數化查詢** (prd §4.6): 所有資料存取不得以字串拼接 SQL，必須使用參數化查詢。
2. **憑證不落版控** (prd §4.6、addendum §C): 密碼以單向雜湊儲存；連線憑證由外部檔案提供，程式碼、文件與版控中不得出現明文密碼。
3. **交易完整性** (prd §4.6): 庫存數量不得為負；造成庫存變動的寫入以交易執行，任一步失敗整筆回滾。
4. **僅追加的稽核資料** (prd §4.6、addendum §D): 庫存異動與銷貨紀錄僅追加，不可修改或刪除；交易類資料不得軟刪除。
5. **查詢效能** (prd §4.6): 在 1,000 筆商品、10,000 筆庫存異動的測試資料集下，清單與明細查詢 2 秒內回應（不含報表彙總與匯出）。
6. **銷售扣減唯一入口** (prd FR-12、FR-16): 銷售用途的庫存扣減只能經由銷貨單；領用不得帶「銷貨」用途。
7. **跨倉只走調貨單** (prd FR-13、FR-14): 任何跨倉庫存變動都必須對應到一張調貨單，位置移轉限於同一倉庫。
8. **角色固定** (prd FR-2): 角色固定四種不可自訂，會計為唯讀。
9. **一專案一資料庫** (addendum §D): 本專案所有資料表集中於單一資料庫（環境中為 `AILearn`），商品、庫存、批次、供應商、銷貨單等實體以關聯共存於同一 schema。

## Done when

1. 四種角色各完成一次自己的主要作業流程：建檔 → 入庫 → 銷售出貨 → 毛利查核 → 補貨判斷（PRD SM-1）。
2. 以固定測試資料集驗證，每個商品的帳面庫存 = 入庫 − 領用 − 調出 + 調入 − 銷貨，誤差為 0；任何跨倉庫存變動都對應到一張調貨單（PRD SM-2）。
3. 任取一筆庫存異動，1 分鐘內可追溯到操作人員、時間、數量、用途與批次（PRD SM-3）。
4. 全程沒有出現庫存數量為負、庫存與異動紀錄不一致、或異動紀錄可被修改的案例（PRD SM-C1）。
5. 系統部署於本機可連線環境，四種角色可登入並操作其權限範圍內的功能。

## Boundaries

- 不做電商前台、線下 POS 與外部客戶的線上訂單（v1 是內部後台）。
- 不做會計總帳、憑證、結帳與稅務處理；會計僅為內部查核角色。
- 不做硬體整合與行動 App；不做條碼／QR／RFID 掃描。
- 不做供應商外部入口（v1 僅維護供應商基本資料）。
- 不做權限自訂與審批流；不做多公司／多租戶。
- 不做庫存盤點與盤盈盤虧、進階報表與圖表、採購單自動產生與寄送流程（PRD §6.2，列為 v2）。
- 共同機制歸屬：R3／R6 的操作人員帶入與異動紀錄寫入機制由 E1（epic-platform-baseline）建立，E3（入庫／領用／移轉／調貨）與 E4（銷貨送出）各自呼叫同一機制產生紀錄；E4 另需產生用途＝銷貨的異動。
- 共同規則歸屬：約束 1～4、6、7（參數化查詢、憑證、交易邊界、僅追加、銷售扣減唯一入口、跨倉必須有調貨單）由 E1 建立守衛規則基線，E3／E4 沿用；技術選型（後端框架、資料庫、架構模式）的歸屬則是 `bmad-architecture` 產生的架構 spine。

- 觸碰點：`AILearn` 資料庫（localhost:5432）— schema 由 epic-platform-baseline 建置並擁有，其餘 epic 只消費；owner: epic-platform-baseline
- 觸碰點：課堂簡報 `庫存管理課題.pptx` — 內容已完整轉寫於 PRD 與 addendum，僅供追溯比對；owner: 無（使用者）
- 觸碰點：課業評分標準 — 外部輸入，影響驗收門檻；owner: 無（使用者）
- 不可改變：交易類資料（庫存異動、銷貨紀錄、批次）不得刪除或軟刪除。
- 跨 epic 的追蹤路徑：登入（E1）→ 建檔（E2）→ 入庫與待補貨清單（E3）→ 銷貨出貨與毛利（E4）→ 毛利查核（E4，會計角色唯讀）。
