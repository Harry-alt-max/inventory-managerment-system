# EXPERIENCE.md — 庫存管理系統

體驗契約：資訊架構、行為、狀態、互動、無障礙與關鍵流程。本文件只管**怎麼運作**；外觀與色碼見 `DESIGN.md`，以 `{path.to.token}` 引用其 token。兩份 spine 與任何 mock、wireframe 或匯入素材衝突時，以 spine 為準。

## Foundation

- **產品**：公司內部的進銷存後台，服務倉管、採購、銷售、會計四種職能。沒有對外流量、沒有註冊、沒有行銷頁面。
- **前端技術**（來自架構 spine AD-16）：React 19 + TypeScript + Vite 的單頁應用，build 產物由 Django 同源供應，開發以 proxy 呼叫後端。
- **認證**（來自架構 spine AD-6）：Django session + CSRF，前端同源呼叫，後端錯誤以機器可讀 `code` 回應（AD-7、AD-17）。
- **金額計算**（來自架構 spine AD-26）：毛利與折後金額由後端報價端點計算，前端不得自行計算；成本缺漏時回 `null` 與 `cost_status="unset"`。
- **UI 系統**：**本 spine 的 UI 層決策**（架構 spine 未涵蓋，待 E1 建置時確認）：shadcn/ui + Tailwind CSS。元件外觀預設可沿用，但密度、間距與色碼一律以 `DESIGN.md` 為準。
- **語系**：繁體中文（zh-TW，預設）與英文（en-US）完整雙語（架構 spine AD-33）；所有字串來自 message catalog，日期、數字、金額格式隨語系切換。
- **色彩模式**：淺色與深色，預設跟隨作業系統。
- **使用情境**：桌機優先、緊湊資訊密度；辦公室桌機與筆電為主。
- **核心主張**：任何一筆數字都能追到「誰、何時、為什麼」——介面永遠把**數字、操作人、時間**放在第一級可見位置。

### 術語對照

專有名詞一律沿用 PRD §3 的定義（**庫存位置**、**庫存異動**、**調貨單**、**領用用途**、**水位**、**批次**、**毛利**），不得改稱。介面上可縮寫為「位置」「異動」，但不得改變語意。

### 導覽規則

- 側邊導覽項目**不依角色改變順序與內容**（避免同一功能在不同人眼中位置不同），而是依角色**顯示／隱藏**；無權限的項目不顯示。
- 使用者選單永遠顯示姓名、角色（唯讀文字）與登出；**語系與色彩模式只在頂列**（唯一權威位置）。
- 任何一頁的「上一頁」都回到其模組清單，而不是回到首頁。
- 庫存查詢清單的視覺基準：[mockups/key-stock-search.html](mockups/key-stock-search.html)。

## Voice and Tone

**語氣**：內部工具的同事說話。簡潔、具體、不推銷。中文為主，術語用產業界慣用詞（入庫、領用、移轉、調貨、批次、水位、可用量、毛利）。

規則：

| 情境 | 寫法 | 不要寫 |
| --- | --- | --- |
| 按鈕 | 動詞開頭：入庫、領用、移轉、建立調貨單、提交銷貨單、儲存草稿 | 確定、OK、送出 |
| 錯誤 | 先說發生什麼，再說怎麼修 | 出錯了、請聯絡管理員 |
| 空狀態 | 說明這個頁面能做什麼 + 給一個動作 | 查無資料 |
| 成功 | 說明結果與下一步 | 操作成功！ |
| 警告 | 說明後果與是否可復原 | 危險！請小心 |
| 數字 | 帶單位與千分位；金額小數兩位 | 1234.5 元 |

範例（雙語並列）：

| 情境 | zh-TW | en-US |
| --- | --- | --- |
| 登入失敗 | 帳號或密碼錯誤 | Incorrect username or password |
| 帳號鎖定 | 連續 5 次輸入錯誤，帳號已鎖定 15 分鐘 | 5 failed attempts. This account is locked for 15 minutes. |
| 可用量不足 | 可用數量不足：需要 100，目前可用 60 | Not enough stock: 100 required, 60 available. |
| 成本未設定 | 此商品尚無入庫成本，毛利無法計算 | No purchase cost recorded for this item; margin cannot be calculated. |
| 毛利為負 | 毛利將為負值，請確認單價與數量 | Margin will be negative. Check unit price and quantity. |
| 空狀態 | 這個頁面會列出低於水位的商品。設定水位後，待補貨的商品會出現在這裡。 | This page lists items below their reorder point. Set a reorder point to see items here. |
| 成功 | 已入庫 50 件六角螺絲 M8×40 至 B 倉 A-03 | Received 50 × 六角螺絲 M8×40 into B 倉 A-03. |

規則：短標籤（按鈕、欄位名、狀態徽章）不加句號；其餘句子使用全形標點；數值與單位之間留半形空白；不使用驚嘆號、emoji 與行銷語氣。英文版中的「B 倉 A-03」是**資料**（倉庫與位置代碼）不是文案，依 AD-33 不隨語系翻譯。

## Component Patterns

元件名稱與 `DESIGN.md` 的 Components **逐一對應**（同名同義）。標示「shadcn 預設」者沿用 shadcn/ui 預設行為。

| 元件 | 行為規則 |
| --- | --- |
| 應用外框 | 側欄可摺疊（≥1024px 展開、<1024px 圖示列）；選取項在導覽與主區標題同步顯示 |
| 頂列 | 全域商品搜尋輸入即過濾（debounce 250ms）；使用者選單點擊外部即關閉 |
| 側邊導覽 | 依角色顯示／隱藏項目；選取狀態持久化於該 session |
| 登入表單 | 失焦即驗證單欄；送出時驗證全表並聚焦第一個錯誤欄位；密碼欄送出後清空、帳號欄保留 |
| 資料表格 | 點表頭排序（單欄遞增／遞減）；分頁；固定表頭；可勾選；數字右對齊等寬；空值顯示「—」 |
| 庫存查詢列 | 表格每列 = 一個商品；展開列顯示各倉各位置可用量；位置代碼以等寬字呈現 |
| 銷貨單編輯 | 表格內直接編輯數量／折扣；摘要條固定於表格下方；重算由後端報價端點回應（AD-26） |
| 數值摘要條 | 顯示原價合計／折扣／折後金額／毛利；毛利值用 `{colors.accent-text}`；成本缺漏時毛利顯示「—」並附說明 |
| 位置選擇器 | 列出「倉庫編號 + 位置代碼 + 可用量」；可用量不足者標示並停用；位置必填 |
| 批次選擇器 | 列出批次序號、採購日期、剩餘數量、單價；預設依 FIFO 建議順序並標「將自動選用」，允許手動改選 |
| 領用作業 | 單一表單：商品、位置、數量、**用途**（客戶寄貨／臨時出貨，無「銷貨」選項）；用途必填；不計毛利 |
| 同倉移轉 | 來源位置與目標位置（同倉）皆必填；跨倉選項不在此畫面，跨倉走調貨單 |
| 調貨單 | 列表 + 明細（來源倉／目標倉／商品／數量／狀態）；建立後即生效；不可刪除，只能作廢並留紀錄 |
| 水位設定 | 表格內可編輯整數水位；編輯後即時顯示「目前庫存／水位／缺口」；低於水位整列標示 |
| 帳號與角色 | 表格 + 抽屜編輯；角色四選一單選（倉管／採購／銷售／會計）；停用後帳號不可登入但紀錄保留 |
| 表單 | 標籤在欄位上方、必填以 `*` 標示；錯誤在欄位下方用 `{colors.danger}`；提交在右下 |
| 狀態徽章 | 狀態色文字 + 對應 `-tint` 底；唯讀／停用用 `{colors.text-muted}` on `{colors.muted-tint}` |
| 空狀態 | 圖示 + 一句說明這個頁面能做什麼 + 一個主要動作按鈕 |
| 二次確認對話框 | 破壞性操作（取消銷貨、停用帳號、作廢調貨單）須寫明「不可復原」與影響範圍；焦點不預設在確認鈕 |
| 草稿提示條 | 銷貨單頁頂部提示「草稿 — 尚未扣減庫存」；草稿可續填或刪除 |
| 骨架載入 | 表格用骨架列、卡片用骨架塊；不用全畫面轉圈 |
| 通知計數徽章 | 頂列小圓點數字；無待辦時不顯示；點擊導向該模組的待辦清單 |
| 抽屜 | 右側滑入；含標題、內容、主／次動作；Esc 關閉；開啟時焦點移入、關閉時還原 |
| 分頁器 | 表格底部右側：上一頁／下一頁／每頁筆數；狀態寫入網址查詢字串 |
| 語系切換 | 頂列切換 zh-TW / en-US；切換不重新整理頁面，保留目前排序、分頁與草稿 |
| 色彩模式切換 | 頂列切換淺色／深色；寫入使用者偏好（server 端保存） |
| 工具列與圖示 | 清單頁右上動作列（新增、匯出）；圖示 16/20px 線性 |

## State Patterns

狀態以「畫面 × 狀態」組織。錯誤狀態標註後端錯誤碼（架構 spine AD-17 的 `code`，前端據此本地化文案）。

| 畫面 | 狀態 | 呈現 |
| --- | --- | --- |
| 全部 | 載入中 | 骨架（表格用骨架列、卡片用骨架塊） |
| 全部 | 空資料 | 圖示 + 說明這個頁面能做什麼 + 一個主要動作按鈕 |
| 全部 | 搜尋無結果 | 與「尚無資料」區分：顯示查詢字串與「清除條件」 |
| 全部 | 未認證（session 過期，401） | 導向 `/login` 並記錄 `return_to`；登入後回到原頁；不丟失草稿 |
| 全部 | 權限不足（403） | 說明「這個功能需要 XX 角色」並顯示目前角色；**只在使用者直接輸入越權網址或 API 403 時出現**（導覽層的無權限項目一律隱藏，不顯示停用狀態） |
| 登入 | 密碼錯誤（`auth.invalid_credentials`） | 表單內訊息「帳號或密碼錯誤」，附失敗次數；密碼欄清空 |
| 登入 | 帳號鎖定（`auth.locked`） | 顯示剩餘鎖定時間與「聯絡倉管解鎖」說明 |
| 入庫 | 欄位缺漏 | 第一個錯誤欄位自動聚焦並捲入視野，欄位下方指出缺哪一欄 |
| 入庫 | 批次缺漏 | 批次為必填（無批次不入庫） |
| 入庫 | 庫存不足（`stock.insufficient`） | 顯示需求與可用數量，提交鈕停用並說明 |
| 領用 | 用途未選 | 用途必填；選項只有「客戶寄貨」「臨時出貨」 |
| 領用 | 超過可用量（`stock.insufficient`） | 顯示可用數量，拒絕提交 |
| 移轉 | 目標位置未選 | 目標位置必填 |
| 移轉 | 跨倉被擋（`stock.cross_warehouse_requires_order`） | 目標位置只能選同倉；跨倉改走調貨單並提示 |
| 調貨單 | 來源倉無足夠量（`stock.insufficient`） | 顯示各倉可用量與缺口 |
| 調貨單 | 已作廢 | 標記「已作廢」並連結原因；不可刪除 |
| 庫存查詢 | 展開列載入中 | 子列骨架 |
| 水位 | 低於水位 | 整列以 `{colors.warning}` 標示，顯示缺口數量 |
| 水位 | 水位值非法 | 只接受非負整數；否則就地提示 |
| 銷貨單 | 草稿 | 草稿提示條「草稿 — 尚未扣減庫存」 |
| 銷貨單 | 重複商品（`sales.duplicate_item`） | 同一商品第二次加入時就地提示並阻止加入 |
| 銷貨單 | 成本未設定 | 毛利欄顯示「成本未設定」徽章、毛利顯示「—」，不得顯示 0 |
| 銷貨單 | 毛利為負 | 摘要區毛利以 `{colors.danger}` 顯示並附說明 |
| 銷貨單 | 批次不足 | 位置／批次選擇器顯示「可滿足 X 件，尚缺 Y 件」 |
| 銷貨單 | 提交後 | 成功摘要（單號、金額、毛利、實際扣減位置）＋兩個動作 |
| 銷貨紀錄 | 沖銷後 | 原單顯示「已沖銷」徽章並連結到沖銷單；原單不可刪除 |
| 商品主檔 | 必填缺漏 | 指出缺哪一欄（名稱、供應商） |
| 供應商 | 統編重複（`catalog.duplicate_tax_id`） | 409，指回既有資料（AD-20） |
| 倉庫與位置 | 位置代碼重複（`catalog.duplicate_location`） | 409，指回既有位置 |
| 倉庫與位置 | 倉庫編碼重複（`catalog.duplicate_warehouse_code`） | 409，指回既有倉庫 |
| 採購批次 | 批次流水號重複（`catalog.duplicate_batch_number`） | 409，指回同日既有批次 |
| 採購批次 | 單價或數量缺漏 | 不可儲存；總價自動計算 |
| 帳號 | 停用帳號嘗試登入 | 拒絕登入；既有紀錄保留 |
| 帳號 | 重設密碼 | 設定新密碼後強制該帳號下次登入需改密 |
| 全部 | 語系切換 | 當頁立即重繪，排序、分頁與草稿保留 |
| 可寫入畫面 | 提交成功 | 成功摘要（結果 + 下一步）＋清單自動刷新；不可逆操作另附「不可復原」提醒 |

## Interaction Primitives

- **全域商品搜尋**：頂列輸入商品編號或名稱，輸入即過濾（debounce 250ms），結果顯示編號、名稱與總可用量；Enter 開啟第一筆。
- **表格排序**：預設依業務時間欄位；點表頭切換；排序與分頁狀態寫入網址查詢字串，可分享與返回。
- **分頁**：預設每頁 50 列，可切 100；狀態同樣寫入網址查詢字串。
- **金額即時試算**：銷貨單任一列變更數量／折扣／批次後呼叫報價端點（AD-26），回應更新摘要條；請求期間摘要顯示載入態但保留舊值，避免閃爍。
- **鍵盤**：表格支援方向鍵移動與 Enter 進入編輯；對話框支援 Esc 關閉；全域快捷鍵 `/` 聚焦搜尋、`n` 在清單頁開啟新增、`s` 在銷貨單頁儲存草稿。
- **表單驗證**：失焦即驗證單欄，送出時驗證全表；第一個錯誤欄位自動聚焦並捲入視野。
- **破壞性操作**：一律二次確認，確認對話框不預設 focus 在確認鈕上。
- **語系與色彩模式**：即時切換，寫入使用者偏好（server 端保存，跨裝置一致）。

## Accessibility Floor

- 對比：正文文字 ≥4.5:1、大字與圖示 ≥3:1、非文字控制項邊框 ≥3:1（淺色與深色兩套皆需通過；`{colors.*}` 為基準，`{colors.border-strong}` 用於可見邊框）。
- 鍵盤可達：所有互動元件可達、可見焦點（`{components.焦點.ring}`），焦點順序與視覺順序一致。
- 表格：使用真實 `<table>` 語義並提供 `<caption>` 與 `scope`；排序欄位以 `aria-sort` 標示。
- 表單：每個欄位有可讀標籤（不只 placeholder）；錯誤訊息以 `aria-describedby` 關聯到欄位。
- 狀態不可只靠顏色：徽章同時有文字（「低於水位」不只是一顆黃點）。
- 動態內容（摘要重算、載入）以 `aria-live="polite"` 通知，不搶走焦點。
- 對比與可達性在實作時以自動化檢查（axe）納入建置流程。

## Responsive & Platform

- 設計基準 1280px 以上；1440px 為主要開發尺寸；各區間的具體行為見 `DESIGN.md` § Layout & Spacing 的「斷點行為」表。
- 1024px 以下：側邊導覽摺疊為圖示列，表格保留水平捲動，摘要條改為可展開的底部列。
- 不做手機專屬版面；手機僅能以瀏覽器開啟且用於查詢與查核，不作為倉管作業裝置。
- 目標環境：Windows 上的 Chrome / Edge 最新版（公司內部桌機）。

## Key Flows

對應 PRD 的 UJ-1～UJ-4（主角沿用 PRD 命名），另有 UJ-5、UJ-6 涵蓋 PRD 未拆成旅程、但有完整行為規格的庫存作業。

### UJ-1 倉管小陳把貨收進 B 倉 A-03

1. 小陳登入 → 落在**庫存現況**工作台，看到今日入庫 0 筆。
2. 他在頂列搜尋「螺絲」→ 找到 `INV-000128 六角螺絲 M8×40` → 進入**入庫作業**。
3. 選倉庫 B → 位置選擇器列出 B 倉各位置與目前數量 → 選 A-03。
4. 輸入數量 50、選批次（系統帶出該採購批次的單價 12.50，不另輸入單價）。
5. 送出 → 成功摘要：「已入庫 50 件六角螺絲 M8×40 至 B 倉 A-03」。
6. **高潮**：庫存現況的「今日異動」立刻出現這一筆，含小陳、時間、數量、批次。
7. **邊界**：數量或位置留空時，欄位下方就地指出缺哪一欄，焦點自動移到第一個錯誤欄位；批次未選時同樣擋下。

視覺基準：[mockups/key-stock-search.html](mockups/key-stock-search.html)

### UJ-2 採購小王看到本週要補的貨

1. 小王登入 → 直接落在**待補貨清單**。
2. 清單顯示 3 項商品：商品名稱、現有庫存、水位、缺口、對應供應商；低於水位的列以 `{colors.warning}` 標示。
3. 他點其中一項 → 抽屜顯示商品主檔、歷史入庫與目前各倉分布。
4. 他建立**採購批次**：選供應商、數量、單價（總價自動計算）、預計到貨日。
5. **高潮**：他回到清單，那項商品仍顯示在待補貨（因為還沒到貨入庫）——但看得到「已下單 200 件」的註記，知道不用重複下單。
6. **邊界**：缺單價或數量時不可儲存並就地指出缺哪一欄；同商品已有未到貨批次時，抽屜提示「已有未到貨批次」並連到該批次。

視覺基準：[mockups/key-replenishment.html](mockups/key-replenishment.html)

### UJ-3 銷售小美賣 3 箱面紙並給折扣

1. 小美登入 → 落在**開單入口** → 搜尋「面紙」→ 看到兩筆：`INV-000207 面紙 L 抽取式`（B 倉 A-07，可售 320，單價 55.00）與 `INV-000208 面紙 擦手紙`（C 倉 B-11，可售 60）。
2. 加入面紙 L 抽取式 3 箱（30 件）→ 銷貨單表格出現；每列可選**位置**。
3. 設定整單折扣 5% → 摘要條即時顯示原價合計 1,650.00、折後金額 1,567.50、毛利 495.00（成本 30 × 45.00，由後端依 FIFO 計算）。
4. 她再加入擦手紙 → 該列顯示「成本未設定」→ 毛利欄顯示「—」，摘要毛利標示「毛利僅計入已設定成本的品項」。
5. **高潮**：她當場把折後金額與毛利回報客戶。
6. 送出 → 成功摘要（單號、折後金額、毛利、實際扣減位置）→ 銷貨紀錄已寫入、庫存已扣減。
7. **邊界**：若面紙只在 C 倉有貨，她依提示建立**調貨單**，由 B 倉調貨後再出貨。

視覺基準：[mockups/key-sales-order.html](mockups/key-sales-order.html)

### UJ-4 會計小周核對一筆銷貨的毛利

1. 小周登入 → 落在**毛利查核**。
2. 依日期或銷貨單號查詢 → 看到每筆銷貨的折後金額、成本、毛利與對應批次。
3. 點入一筆 → 明細顯示批次消耗（依 FIFO 的消耗明細）與操作人員。
4. **高潮**：毛利與預期一致，核對完成；全程唯讀，任何寫入鈕都不出現。
5. **邊界**：查無單號時顯示「查無資料」並提示可用日期區間查詢與「清除條件」。

### UJ-5 銷售小美發現面紙只在 C 倉，開一張跨倉調貨單

1. 小美在銷貨單上看到某商品在 B 倉可用量為 0、C 倉有貨，畫面標示「建議調貨來源：C 倉」。
2. 她點「建立調貨單」→ 調貨單畫面帶入商品、數量、來源倉 C、目標倉 B。
3. 她送出 → 調貨單即時生效，產生移出與移入兩筆庫存異動，兩筆都可對應回這張調貨單。
4. **高潮**：回到銷貨單，該商品在 B 倉的可用量已更新，可直接出貨。
5. **邊界**：C 倉可用量不足時，調貨單擋下並顯示各倉可用量與缺口；若嘗試用「移轉」跨倉，介面擋下並提示「跨倉請改用調貨單」。

### UJ-6 倉管小陳領用與同倉移轉

1. 小陳在**庫存現況**看到倉管待辦（有一張領用單待處理）→ 進入**領用作業**。
2. 選商品與位置 → 輸入數量 → 選用途「客戶寄貨」→ 送出。
3. **高潮**：庫存現況的今日異動出現「小陳 領用 10 件（客戶寄貨）」，且該筆**不計毛利**。
4. 他接著把 5 件由 B 倉 A-03 移到 B 倉 A-04（同倉移轉）→ 移出與移入各一筆異動，總庫存不變。
5. **邊界**：領用數量超過可用量時被拒絕並顯示可用數量；移轉的目標位置若選到其他倉庫，介面擋下並提示改用調貨單；移轉時來源位置數量不足同樣被拒絕。
