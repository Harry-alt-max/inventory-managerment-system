# Editorial Review — PRD: 庫存管理系統（Prose Lens）

## 一句话定位（讀者校準）

這份文件存在，是為了讓專案團隊與後續工作流（`bmad-ux`、`bmad-architecture`、票據拆解）**在同樣的「要做什麼／怎麼驗收」理解下**把課業規模的庫存系統切成可實作、可驗收的項目。

- **受審內容**：`prd-inventory-management-system.md`（正文 6,352 字，經 `word_metrics.py` 計；另有同資料夾 `addendum.md` 作為交叉引用情境）
- **讀者**：台灣讀者、繁體中文、課業／作業規模 PRD，寫作傳統採 Microsoft Writing Style Guide 風格
- **前序**：結構（Structure）lens 已先行並部分套用其建議（§9 表格化、§8 重構、FR 邊界劃界、FR 編號修正）。本輪僅做**行文層面的精修**，不重做結構、不改動需求內容。
- **保留的作者語氣**（不列為問題）：§1 Vision 的口語化敘事（「賣得掉嗎、賺不賺」「跨好幾個人對答案」）、§2.3 使用者旅程的「高潮／邊界／收尾」標記、§4 各 FR 統一採「Description → Functional Requirements → Consequences (testable)」骨架。這些是刻意的敘事節奏，應保留。

## 三、彙整

- **Prose 建議總數**：26 列（其中 3 列為連動／跨檔修改，1 列為選用）。
- **若全數接受**，估計可減少約 250～350 字（約佔原文 4～5%）；本文件**未設字數上限**，長度目標不適用。主要收益不在字數，而在**消除互相矛盾的讀法**（FR-6 vs FR-13／FR-14、FR-11 vs FR-4／FR-9、FR-12 vs §3、§3 毛利 vs §8.1、§8.4 斷頭參照、§0 不實宣稱）。
- **依影響排序的 5 項必處理**：
  1. FR-6「只產生一筆異動紀錄」與移轉／調貨的兩筆異動衝突（影響正確性驗收、SM-2 對帳）
  2. FR-12「用途＝銷貨」與「銷售出貨一律走 FR-16」自我否定（影響資料流程唯一性，需連動改詞彙表與 §9）
  3. FR-11「輸入採購單價」與 FR-4／FR-9 的單價引用制衝突（影響成本可追溯與 FR-18 成本基準）
  4. §3 角色指向不存在的 §8.4（斷頭參照）
  5. §0「FR 與 UJ 以 ID 互相引用」與實情不符（導言層級的誤導）
- **術語一致性的四組待收斂**：移位／移轉、提取／異動數量、操作人員／銷貨人員、領用用途的「銷貨」選項名稱。建議在同一輪編輯中一次改完，避免逐條套用造成新的不一致。
- **理解取捨**：本輪所有建議皆不犧牲讀者參與度——§1 的敘事語氣、UJ 的「高潮／邊界／收尾」結構與 §4.6 的評分備註皆原樣保留；唯一的「削減」是把 FR-15 與 FR-5 的重複說明從 `[ASSUMPTION]` 標籤中移出，改為 FR-15 正文首句，屬位置變更而非內容刪減。
